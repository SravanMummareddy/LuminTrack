# 27 — Prisma (ORM) trade-offs

> **In plain English.** Prisma is an ORM — Object-Relational
> Mapper — a library that lets you write database queries in
> TypeScript instead of raw SQL, and gets you generated types
> from your schema. There are alternatives (Drizzle, Kysely, raw
> SQL with `pg`) and each has a different point on the
> "abstraction vs control" spectrum.

## The technical core

### The ORM spectrum

| Tool          | Style                       | Type safety  | SQL closeness |
|---------------|-----------------------------|--------------|---------------|
| Raw `pg`      | Strings + parameters         | None         | Full          |
| Kysely        | SQL builder, typed           | Full         | High          |
| Drizzle       | SQL builder, typed           | Full         | High          |
| Prisma        | ORM with custom query DSL    | Full         | Medium        |
| TypeORM/Sequelize | Class-based ORM          | Partial      | Low           |

Prisma sits in the middle: real type safety, ergonomic API,
slightly further from SQL than Drizzle.

### Prisma's strengths

- **Schema as source of truth.** `schema.prisma` is one file;
  client + migrations + types generate from it.
- **Type safety end-to-end.** Hover a result, see exact shape.
- **Migrations.** `prisma migrate dev` creates timestamped
  `migration.sql` files. Pure SQL, reviewable.
- **Prisma Studio.** A GUI for the DB — invaluable in dev.
- **Driver adapters.** Pure-JS drivers that work in any runtime,
  including Edge (see [`26-edge-vs-node-runtimes.md`](./26-edge-vs-node-runtimes.md)).

### Prisma's weaknesses

- **N+1 risk.** Loading relations is easy with `include`, but if
  you `include` inside a map you've spawned N queries.
- **Aggregations beyond simple ones drop to raw SQL.** Window
  functions, CTEs, full-text search — use `$queryRaw`.
- **Schema is the only DDL surface.** No views, no triggers
  (today). Stored procedures via raw SQL only.
- **Generator output is huge.** The client is heavy; ships fine
  but ages the bundle.

### When you'd reach for raw SQL

- Reporting queries with window functions / CTEs (LuminTrack's
  time-in-stage walk uses a manual loop in TypeScript instead;
  could be SQL).
- Anything `EXPLAIN ANALYZE` told you to hand-optimise.
- DDL Prisma doesn't model (triggers, partial unique indexes
  with conditions).

## Where it lives in LuminTrack

- `prisma/schema.prisma` — all models, enums, migrations source
  of truth.
- `prisma/migrations/*` — SQL files generated by `prisma migrate
  dev`.
- `src/server/db.ts` — `PrismaClient` with `PrismaNeon` adapter.
- `src/server/queries/*.ts` — typed read functions.
- `src/server/actions/*.ts` — `prisma.$transaction` everywhere.
- One raw query in the codebase: the advisory-lock call in
  `src/server/actions/ilabor-import.ts`.

## How to talk about it in an interview

**Sample answer (75 sec):**

> "I picked Prisma over Drizzle and raw SQL for LuminTrack
> because the schema-as-source-of-truth model is hard to beat at
> a small team's scale — one `schema.prisma` file generates the
> client, the migrations, and the types. Hover any result, see
> the shape. The cost is that complex aggregations don't always
> map cleanly — the Reports page's time-in-stage logic walks the
> audit log in TypeScript rather than as a Postgres CTE, which
> is acceptable for our row counts but would need rewriting at
> 100x. The other Prisma gotcha that bit me was that the v7
> client requires a *driver adapter* — `@prisma/adapter-neon` —
> not the bundled engine. And Prisma's `Decimal` isn't
> serializable across the RSC boundary, so query functions
> flatten Decimal fields to strings before returning. If I were
> starting again at the same scale I might try Drizzle for its
> closer-to-SQL feel, but I'm not unhappy with Prisma."

**Expect:**

- "What's an N+1 query?" → Loading the parent then issuing a
  query per child. Prisma's `include` solves it; the wrong
  pattern is mapping then querying.
- "How do you handle migrations in CI?" → `prisma migrate
  deploy` in the deploy step; never `migrate dev` in CI.
- "What if Prisma's query builder can't express what you need?"
  → Drop to `$queryRaw` with parameterised template strings.

## Mistakes to avoid saying

- ❌ "ORMs are slow." Usually no; the slow part is your queries.
- ❌ "I'd never use an ORM in prod." Many massive-scale apps run
  on Prisma / similar. Trade-off, not absolute.
- ❌ "Drizzle is just a Prisma clone." They have different design
  philosophies; Drizzle is closer to a SQL builder.
